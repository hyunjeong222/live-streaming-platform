# 노션 정리

프로젝트를 진행하며 함께 정한 중요한 것들을 노션에 남긴다. 저장소의 ADR(`docs/decisions/`)은 짧은 결정 기록이고, 노션은 나중에 다시 읽기 좋은 정리본이다.

## 위치

위치와 표 구성은 `CLAUDE.md`의 "프로젝트 정보 > 노션 정리"에 적는다. 이 스킬은 그 값을 읽어 쓴다.

- 페이지: 프로젝트 정리 페이지
- 표: 페이지 맨 앞의 인라인 표. 표 한 행이 문서 하나다.
- 열: `CLAUDE.md`에 정한 열을 따른다.

`CLAUDE.md`에 페이지나 표 열이 아직 정해지지 않았으면 노션에 쓰지 않는다. 무엇이 비었는지 알리고, 정할 값을 사용자에게 묻는다.

표가 아직 없으면 사용자 승인을 받아 페이지 맨 앞에 인라인 표로 만든다. 만든 뒤 표의 주소를 `CLAUDE.md`에 적을지 묻는다.

## 언제 쓰나

- 기능 하나를 마쳤을 때, 대안 중 하나를 골랐을 때, 막혔던 문제를 풀었을 때
- 이름 변경이나 단순 수정처럼 남길 고민이 없는 작업은 쓰지 않고, 없다고만 알린다.
- 결정의 이유는 대화에만 있으므로 `/clear`나 `/compact` 전에 같은 세션에서 쓴다.

## 절차

1. **근거를 모은다.** 이슈(`gh issue view`), 커밋(`git log origin/dev..HEAD`), 변경 파일, 이 대화에서 오간 결정과 버린 대안을 본다. ADR이 있으면 그 내용을 바탕으로 쓴다.
2. **초안을 쓴다.** 표의 열과 본문 구성은 `CLAUDE.md`에 정한 것을 따른다. "무엇을 결정했고, 어떤 선택지가 있었고, 왜 골랐는지"라는 핵심만 쓰고 구현 과정을 늘어놓지 않는다. 확인하지 못한 주장은 문장 앞에 `(미확인)`을 붙인다.
3. **민감정보를 점검한다.** 초안을 임시 파일로 저장해 검사한다. 노션도 공유될 수 있으므로 저장소 문서와 같은 기준을 쓴다.
   ```bash
   bash .claude/skills/session-summary/scan-sensitive.sh <초안 파일>
   ```
   걸리면 그 줄을 지우거나 일반화한다. 비밀번호, 토큰, 키, 환경변수 값, 내부 주소, 개인정보를 쓰지 않는다.
4. **사용자에게 확인받는다.** 열에 넣을 값과 본문 초안을 보여주고 **명시적 승인**을 받는다. 승인 전에는 노션에 쓰지 않는다.
5. **승인 후 노션에 쓴다.** 표에 행(페이지)을 하나 만들고 열과 본문을 채운다. 쓴 뒤 페이지를 다시 읽어 확인하고 링크를 알린다.

## 하지 않는 것

- 이미 있는 행을 승인 없이 고치지 않는다. 고칠 때도 초안을 먼저 보여준다.
- 코드나 설정값을 그대로 옮기지 않는다. 파일 경로와 이름으로 가리킨다.
